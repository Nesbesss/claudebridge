Authentication

ClaudeBridge handles authentication at the kernel level. To communicate with upstream providers like OpenAI, Anthropic, or Groq, you must provide valid API keys. These are securely managed in your local environment.

Environment Variables

The bridge automatically looks for keys in ~/.claudebridge.env. You can also set these variables in your active terminal shell.

.env TEMPLATE
OPENAI_API_KEY=sk-proj-...
ANTHROPIC_API_KEY=sk-ant-api03-...
GROQ_API_KEY=gsk_...
MISTRAL_API_KEY=...

Interactive Injection

If you don't want to store keys in a flat file, you can use the --wizard to securely input them into memory for the current session, or use the --api-key flag during startup.

CLI
claudebridge --provider openai --api-key sk-...

Local Providers

For local nodes like Ollama, authentication is usually not required. ClaudeBridge defaults to null-auth for any localhost or 127.0.0.1 endpoints unless otherwise specified in your profile config.

Provider Security

Encryption: ClaudeBridge does not encrypt keys on disk by default to maintain compatibility with standard .env workflows. Ensure your home directory permissions are restricted (chmod 600 ~/.claudebridge.env).
