Semantic Caching

ClaudeBridge includes a built-in semantic caching layer that stores LLM responses locally. Unlike traditional exact-match caching, ClaudeBridge can identify "similar" queries and serve cached results, significantly reducing both your API bill and response latency.

The Caching Kernel

When enabled, every outgoing request is hashed and indexed. Before sending a new request to an upstream provider (like OpenAI or Anthropic), the kernel checks its local database for a match.

Similarity & TTL

  • Semantic Matching: Uses vector embeddings to determine if two prompts have the same intent, even if the phrasing is different.
  • TTL (Time To Live): Cached entries remain valid for 24 hours by default, ensuring you aren't served stale information in fast-moving dev environments.
  • Storage: Cached results are stored in ~/.claudebridge/cache.json.

Management Commands

You can control the cache state directly from your chat session using live intercepts.

INTERCEPT
$$cache on
$$cache off
$$cache clear
Performance Impact: A cache hit typically returns in under 10ms, compared to the 1000ms+ latency of a standard cloud LLM request.
