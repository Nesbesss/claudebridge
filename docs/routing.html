Agentic Routing

ClaudeBridge's Smart Routing kernel is designed to optimize for both speed and cost. By analyzing the intent and complexity of incoming prompts, the bridge can dynamically steer requests to the most appropriate model node in your cluster.

How it Works

When a request enters the V1/Messages endpoint, the Routing logic performs a near-instant classification based on three primary vectors:

  • Intent: Is this a creative task, a logic puzzle, or a simple system command?
  • History length: Does the task require a large context window (e.g., 100k+ tokens)?
  • Tool availability: Does the user need complex function calling or just text completion?

Classification Engine

Task TypeRouted Node
Logic/CodingGPT-4o or Claude 3.5 Sonnet
SummarizationLlama-3-70B or Mistral Large
Quick ChatGroq / Llama-3-8B
System InterceptLocal Kernel (Zero-Node)

Configuration

Routing is off by default. You can enable it via the CLI or by setting the environment variable in your ~/.claudebridge.env.

CLI
claudebridge --enable-routing --fallback-chain groq,openai
Performance: The routing overhead is approximately 1.2ms, which is completely negated by the speed gains of using optimized small-model nodes for simple tasks.
